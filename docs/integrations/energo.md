# EnerGO: модуль по контракту Юрент v1.0, май 2026

Дата проверки: 17 октября 2026. База: `ba236bb` (main).
Источник: «Интеграция_провайдера_павербанков_в_платформу_Юрент.pdf», 10 страниц, предоставленный пользователем.
Прочитан полный документ. Это требования к API провайдера для Юрент, а не подтверждение доступа MIRA LINK к работающему API EnerGO.

## Что изменено

- Существующий `PowerbankProviderAdapter` сохранён. Добавлен серверный `EnergoPowerbankProviderAdapter`.
- `GET /v1/public/map` и `/map/station/{stationId}`: проверка схем, доступность, свободные слоты, фильтрация скрытых станций. Для связи с заведением нужна явная таблица `venueByStation`; она не выводится из названия или координат.
- QR сопоставляется точно с `stationQr` из карты. Никакого перехода по QR URL, выбора первой станции или угадывания short code. Дубли QR отклоняются. В демо `demo-terminal` явно связан с одной станцией; неизвестный/пустой терминал больше не подставляет её.
- Создание сессии передаёт `stationShortCode` и `activityId`. Ключ и гость обязательны. `Preparation` не считается успешной выдачей.
- Опрос известной аренды и обработчик callback. `Closed/2` — физический возврат; `Closed/3` — отказ выдачи; `Closed/4` — закрытие провайдером. Событие закрытия не запускает оплату.
- Журнал SQLite хранит ключ, гостя, станцию и последний статус. Уникальный ключ и одна незавершённая операция на гостя защищены транзакциями и индексами. Повторы и регрессирующие статусы не меняют финал. Конфликтующие финальные состояния требуют сверки.
- GET имеет ограниченные повторы при сетевых ошибках и 502/503/504. POST выдачи отправляется ровно один раз. Таймаут, неверный ответ и ошибка сохранения после выдачи оставляют запрос нерешённым. Повтор с тем же или новым ключом не выдаёт ещё одно устройство.
- Тариф и текущая стоимость не выдумываются: контракт их не содержит. Числа 99/50 ₽ остаются только в явно помеченном деморежиме.
- Готовая страница сохранена; изменены QR-проверка, сообщение об ошибке и обозначение демо. Она по-прежнему подключена к демо, а не к серверному EnerGO.

## Реальные ограничения этого изменения

Продакшен-выдача **заблокирована кодом**. Даже `mode: 'production'` разрешает только чтение при явном `contractConfirmed: true`. Sandbox-выдача требует отдельного `sandboxDispatchEnabled: true`; включать только с подтверждённым тестовым URL и тестовым терминалом. В этой работе все HTTP-ответы были локальными заглушками; подключений к EnerGO и списаний не было.

`/close` не вызывается: принудительное закрытие не доказывает физический возврат. `/withdraw` не реализован: по документу это уведомление о уже состоявшемся списании, а не платёжный API.

Нет публичного HTTP endpoint или подключения демо-интерфейса к секретам. В текущем репозитории бизнес-состояние демо находится в localStorage, нет серверной авторизации владельца аренды. Выносить токены в браузер нельзя.

SQLite — рабочая реализация для Node >=22.13 на постоянном диске (например, отдельный Node backend). `node:sqlite` нельзя подключать к Cloudflare Worker. Для текущего Worker-развёртывания нужен эквивалентный `EnergoJournal` на D1/Durable Objects с теми же атомарными гарантиями. Для нескольких серверов без общего SQLite-диска нужен единый сервер БД/журнала. Не размещать файл в эфемерной файловой системе и не хранить его в git.

`getRental` и `handleCallback` — внутренние серверные методы. Публичный BFF должен проверять владельца аренды до вызова, получать guestReference из доверенной сессии, а не JSON браузера, ограничивать размер body, частоту запросов и доступ к операторским действиям. `getRental` не импортирует неизвестные ID.

Неопределённые операции не истекают и не повторяются автоматически. Даже ошибка предварительной проверки станции после записи claim оставляет блокировку; это консервативная политика прототипа. Перед запуском нужна отдельная операторская процедура отмены доказанно неотправленного запроса и сверки неоднозначной выдачи. Нельзя просто удалять ключ и повторять POST.

Callback до ответа POST пока отклоняется с `UNKNOWN_SESSION_RETRY_REQUIRED`: документ не содержит `activityId` в событии, поэтому привязка по станции небезопасна. HTTP-обвязка должна надёжно сохранять такие события в inbox и обрабатывать после связывания сессии, либо договориться о гарантированных повторах провайдера. Не отвечать 200 до сохранения события/состояния. Неправильный callback-токен по этому контракту соответствует HTTP 400. Известный повтор после сохранения — HTTP 200. Неизвестный sessionId нельзя считать успешным.

В документе нет последовательного номера события. Модуль запрещает регрессию состояния, но конфликт финальных событий отправляет на сверку. `Preclosed` сохраняется как `returning`; допустимые сочетания reason-кода требуют подтверждения (сейчас принимаются 1/2/4). `GET /sessions/{id}` с HTTP 409 не считается доказанным возвратом и требует сверки.

`map_basic` и список сессий по статусу пока не используются: первое — оптимизация; второе не даёт гарантированного поиска по `activityId`. Карта не вычисляет расстояния, рабочие часы или радиус «рядом»: для этого нужны геопозиция и правила расписания/часового пояса. Возвратные станции фильтруются по active/online и свободным слотам, а физическая доступность помещения требует отдельного расписания.

## Минимальное подключение на тестовом Node backend

```ts
import {EnergoPowerbankProviderAdapter} from '../../lib/powerbank/energo.server';
import {SqliteEnergoJournal} from '../../lib/powerbank/sqlite-journal.server';

// Секреты только из серверного secret manager, без NEXT_PUBLIC_*.
const journal = new SqliteEnergoJournal('/persistent-data/energo.db');
const adapter = new EnergoPowerbankProviderAdapter({
  baseUrl: process.env.ENERGO_SANDBOX_ORIGIN!, // HTTPS origin, без пути
  token: process.env.ENERGO_API_TOKEN!,
  callbackToken: process.env.ENERGO_CALLBACK_TOKEN!,
  contractConfirmed: true, // Только после подтверждения EnerGO
  mode: 'sandbox',
  sandboxDispatchEnabled: false, // Включать отдельно после допуска к тестам
  venueByStation: {}, // stationId провайдера → venueId MIRA LINK
}, journal);

const station = await adapter.resolveTerminal(scannedRawQr);
// Известная авторизованная личность + сохранённый ключ намерения пользователя.
// Повтор нажатия/перезагрузка должны использовать тот же ключ.
const rental = await adapter.startRental({
  stationId: station.id, guestReference: authenticatedGuestId,
  idempotencyKey: persistedActivityId,
});
```

Это пример для будущего BFF, не активный endpoint. Не добавлять реальный адаптер в `createDemoPowerbankService`. Клиент должен получать очищенные DTO через BFF; серверные модули не импортируются в React.

## Что запросить у EnerGO

| Данные / согласование | Почему необходимо |
|---|---|
| Подтверждение права MIRA LINK работать напрямую и актуальной версии API | Контракт адресован Юрент; права и совместимость не следуют из PDF |
| Sandbox и production HTTPS origin, токены, scopes, IP allowlist, ротация, ProviderApiName | Реальное подключение и изоляция сред |
| Тестовый терминал, QR целиком, stationId, stationShortCode, связь с заведением | Проверка выдачи именно из отсканированного терминала |
| Синхронный/асинхронный режим, реальные примеры ответов и всех status/statusCode, 404/409 | Валидация состояния и ошибок |
| Гарантия дедупликации `activityId`, её срок; поиск сессии по activityId или эквивалент | Без этого неоднозначный POST нельзя автоматически повторить или восстановить |
| URL/токен callback для MIRA LINK, политика повторов, ACK, порядок, eventId/sequence; activityId в событии | Надёжная доставка, ранние и дублирующиеся события |
| API тарифов либо подписанная конфигурация: валюта, интервалы, округление, бесплатное время, депозит, лимиты, потеря, версии и срок действия предложения | Нельзя показывать реальную цену или заключать аренду по демотарифу |
| Кто принимает деньги, предавторизация, платёжный/фискальный контур, возвраты, комиссия; необходимость `/withdraw` | Контракт не предоставляет API списания; это отдельный проектный блок |
| Правила `/close`, возврата в другую станцию, ручных корректировок и спорных событий | Закрытие сессии не всегда физический возврат |
| Частота карты, лимиты запросов, политика 429/Retry-After, SLA, свежесть остатков, время работы/часовой пояс | Эксплуатация и корректное отображение доступности |

## Что доделать в MIRA LINK перед production

1. Выбрать серверное размещение и постоянную БД; подключить журнал к нему.
2. Реализовать авторизованный BFF, привязку гостя и аренды, rate limit и аудит без секретов.
3. Реализовать durable webhook inbox, периодическую сверку и операторский разбор неизвестных результатов.
4. Получить реальные тарифы, показать согласие пользователя с версией тарифа; утвердить платёжный контур отдельно.
5. Подключить существующий интерфейс через BFF; отображать preparing/returning/failed/closed, периодический опрос с отменой при уходе со страницы. Для внешнего EnerGO QR передавать исходную строку в `resolveTerminal`, не пытаться применять MIRA QR-парсер.
6. Пройти тесты на физическом sandbox-терминале, согласовать расписание и возвраты. Только после этого отдельным изменением разрешать production dispatch.

## Проверки

- `npm run test:powerbank`: 16 тестов, все прошли (локальные HTTP mocks + настоящий SQLite).
- `npm test`: 58 существующих доменных тестов, все прошли.
- `npm run typecheck`: прошёл.
- В `tests/e2e/guest-powerbank.spec.ts` добавлены проверки неизвестного QR и выбора другой конкретной станции. Браузерный прогон не выполнен: установка Chromium завершилась ошибкой (загруженный архив повреждён/пуст). Системный браузер отсутствует. Новые e2e-сценарии требуют прогона в CI.

Тесты покрывают сохранение после перезапуска, два подключения к журналу, конфликт ключа, повторное нажатие, неизвестный результат POST, таймаут, ограниченные GET retries, отсутствие повторов 401, проверку callback, возврат/отказ/принудительное закрытие, поздние события, неверные DTO и изоляцию демо. Они не подтверждают совместимость с ещё не предоставленным работающим API EnerGO.
