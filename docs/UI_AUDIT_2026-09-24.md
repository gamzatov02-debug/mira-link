# Проверка соответствия визуальному ТЗ MIRA LINK

Проверен текущий проект, без второго приложения и без новых версий маршрутов.

## Обнаружено и исправлено

| Требование | Найденное несоответствие | Исправление |
|---|---|---|
| Премиальные фотографии | URL интерьерного фото возвращал 404; фото блюда зависело от стороннего хоста | Локальные изображения; рабочее фото блюда сохранено, недоступный интерьер заменён |
| Компактная мобильная композиция | Демо-шапка и переключатель устройств вытесняли содержимое | Компактная шапка, навигация ролей с внутренним скроллом, устройства в раскрываемом блоке |
| Единая карточка блюда | На главной и в меню разные способы отображения фото; в диалоге фото отсутствовало | Общий ProductImage, стабильные размеры и fallback при ошибке загрузки |
| Quiet luxury | Два крупных рекламных блока после оформления заказа, чрезмерный размер приветствия | При активном заказе приоритет его статусу; уменьшена типографика гостевой шапки |
| Empty states | Пустой поиск и некоторые разделы не сообщали об отсутствии данных | MiraEmptyState в поиске, гостях, истории, избранном, уведомлениях, вызовах и Cash Pending |
| Операционный интерфейс официанта | Не было карты назначенных столов, фильтров и личной суммы чаевых | Представления существующих данных, без новых команд и финансовых расчётов в engine |
| Выбранные состояния | Проценты чаевых не выделялись | aria-pressed и общее selected-оформление с учётом текущей суммы |
| Понятные пользовательские тексты | Технические TODO выводились в гостевой оплате и профиле | Понятное описание недоступных возможностей; неутверждённые условия остались неактивными |
| Guest notifications/history/favorites | Данные были доступны только фрагментами | Отдельные представления в существующем Guest и меню «Ещё» |
| Demo Hub / Full Cycle | Не было прямого переключения между ролями | Навигация Guest / Waiter / Admin / Full Cycle в общей шапке |

Также исправлено активное состояние Bottom Navigation на вложенных экранах, добавлен viewport-fit=cover для safe-area. «О месте» открывает единый MiraModal с существующими данными заведения и переходом в прежнюю форму бронирования.

## Сохранено

Исходная монограмма, палитра, Manrope, нижняя навигация из пяти пунктов. Используются существующие MiraButton, MiraIconButton, MiraCard, MiraChip, MiraStatusBadge, MiraModal, MiraEmptyState и доменные карточки.

Изменения относятся к presentation-слою. SHA-256 `engine.ts`, `model.ts`, `seed.ts`, `selectors.ts`, `store.ts`, `adapters.ts` совпадают с baseline до визуальных изменений. Исходные 9 бизнес-E2E не переписывались.

## Границы соответствия

Полное соответствие визуальному ТЗ не заявляется: отдельного оригинального SVG/PNG логотипа и фотографий большинства блюд нет. Монограмма остаётся растровой, блюда без фото имеют нейтральный общий placeholder. Промокоды, тарифы и сетевые правила остаются неутверждёнными продуктовыми решениями. Новые финансовые правила не придуманы.

Shared state синхронизируется между вкладками одного браузерного профиля/origin, как и до проверки. Серверная синхронизация разных физических устройств в визуальную задачу не добавлялась.
