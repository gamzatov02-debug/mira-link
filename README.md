# MIRA LINK

Интерактивное ресторанное демо в существующем проекте: сайт, гость, официант и кабинет заведения. Все операции демонстрационные; внешние заказы и списания не выполняются.

## Запуск

Node.js >=22.13, npm. Из этой папки:

```sh
npm ci
npm run dev -- --port 5173
```

Открыть http://localhost:5173/demo. Для полного сценария — `/demo/full-cycle`.

## Маршруты

- `/` — сайт-визитка.
- `/demo` — выбор режима.
- `/demo/guest/home`, `/demo/guest/welcome` — гость и QR-вход.
- `/demo/guest/menu`, `/demo/guest/order`, `/demo/guest/bill`, `/demo/guest/waiter` — ресторанный цикл.
- `/demo/guest/nearby`, `/demo/guest/events`, `/demo/guest/promotions`, `/demo/guest/more` — дополнительные разделы.
- `/demo/guest/bonuses`, `/demo/guest/profile`, `/demo/guest/booking`, `/demo/guest/review`, `/demo/guest/tips`.
- `/demo/guest/powerbank`, `/demo/guest/taxi`, `/demo/guest/wifi`, `/demo/guest/delivery`.
- `/demo/waiter` — смена официанта.
- `/demo/admin` — кабинет, 20 разделов внутренней навигации.
- `/demo/full-cycle` — три синхронные панели и пошаговые подсказки.

Гостевые подразделы доступны как прямыми URL, так и внутренней навигацией. Интерфейс администратора переключает разделы без отдельной загрузки страницы.

## Архитектура

- `lib/domain/model.ts`: сущности и целочисленные суммы в копейках.
- `lib/domain/engine.ts`: команды, проверки инвариантов, события. Команда применяется к копии; некорректная операция не меняет исходное состояние.
- `lib/domain/selectors.ts`: счёт, общий заказ, остаток, аналитика.
- `lib/domain/seed.ts`: 12 столов, 16 блюд, сотрудники и бонусный аккаунт.
- `lib/store.ts`: единый state, localStorage, BroadcastChannel + storage events, Web Locks против одновременной перезаписи вкладками.
- `lib/adapters.ts`: заменяемые демонстрационные POS / Payment / Taxi / Powerbank adapters.
- `components/demo-app.tsx`: рабочие поверхности; существующие брендовые компоненты в `components/mira.tsx` переиспользуются.

State общий только для вкладок одного браузерного профиля и origin. Для совместной работы разных устройств нужен сервер; в этом демо он не эмулируется. Переключатель демо-устройства намеренно позволяет исследовать несколько гостей. Это не production-аутентификация. Существующие заготовки D1 и ChatGPT-auth сохранены, но не подключены к ресторанному state.

## Как пройти цикл

1. Откройте полный цикл и включите демо-аккаунт перед QR-входом первого гостя.
2. Раскройте «Гости и устройства демо», создайте второе устройство, отсканируйте стол, подтвердите присоединение. Первый скан не открывает чужой заказ.
3. Выберите гостя, блюдо и дополнения, перейдите в «Заказ», оформите. Повторите для второго гостя.
4. У официанта подтвердите iiko; вызовите официанта у гостя и примите вызов у сотрудника.
5. В счёте выберите Split, бонусы и чаевые, создайте онлайн-платёж, симулируйте успех. Кешбэк начисляется сразу.
6. Сделайте дозаказ. Исторический платёж не изменится. Оплатите оставшиеся части.
7. У официанта отметьте заказы поданными; в кабинете → «Зал и столы» закройте посещение.
8. У гостя → «Поблагодарить»: отдельные чаевые после закрытия не меняют средний чек и число посещений.

Наличные подтверждаются только кнопкой POS у официанта. Ошибку POS и задержку можно задать в кабинете → «Интеграции». Там же задаётся демонстрационная комиссия: seed равен 0, коммерческий тариф не утверждён. Глобальный сброс восстанавливает точный seed во всех вкладках.

## Проверки

```sh
npm run typecheck
npm test
PLAYWRIGHT_BROWSERS_PATH=.test-runtime/browsers npx playwright install chromium
npm run test:e2e
npm run build
```

Playwright использует локальный dev-сервер (запускает его автоматически, если не запущен). Тесты изолируют браузерные контексты; пользовательские данные открытого демо не меняются. `.test-runtime` и результаты тестов исключены из Git.

## Неутверждённые решения

- Финансовые условия Promotion / персональных PromoCode и совместимость скидок. До утверждения скидки не рассчитываются; форма явно сообщает об этом.
- Постоянные ставки комиссии и тарифные цены.
- Реферальные вознаграждения, объединение столов, сетевой доступ к данным.
- Дополнительные refund rules; существующая доменная заготовка возвратов не выведена в UI как утверждённая политика.

Монограмма отображается из первого предоставленного JPEG-референса через CSS viewport без перерисовки. Для более высокого разрешения и прозрачного фона нужен отдельный оригинальный SVG/PNG. Подробности — docs/DESIGN_REFACTOR.md.
